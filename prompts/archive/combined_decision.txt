## Delegation classification

You must pick `delegation_tier` (0, 1, or 2). Before classifying, read the capability manifest below so you know what each tier can actually do. Then fill in `delegation_checklist`, then derive the tier using the rule. Do NOT pattern-match on surface keywords — reason from capabilities.

### Capability manifest (what each tier can actually do)

These are the CONCRETE operations available behind each tier. Classify by fit-to-capability, not by vibe.

- **`delegation_tier: 0` (pure reply).** PaLLi replies directly from training + conversation history. No tools run. Nothing external is consulted. Fast (seconds). Use for: general knowledge, conversation, textbook answers, opinions, emotional check-ins, greetings, acknowledgements.

- **`delegation_tier: 1` (ONE in-house tool call).** Exactly ONE of:
  - `web_search(query)` — returns a short snippet of web results
  - `url_browse(url)` — fetches and summarizes a specific URL
  - `screenshot()` — one screenshot of the user's desktop
  - `schedule_reminder(when, what)` — creates a reminder
  - `list_reminders()` / `cancel_reminder(ref)` / `reschedule_reminder(ref, when)` — reminder lifecycle ops
  - `deliver_artifact(path)` — sends a pre-existing file to the user
  - `local_shell(command)` — runs ONE shell command directly on the host (no Claude Code SDK in path; uses autonomy policy + intent classifier for safety). Use for: "check git status", "list processes", "what's in this directory", "kill that hung process", "ssh into my box". The command goes in `delegation_task_hint`.
  - `read_file(path)` — reads ONE file from the workspace or watch dirs. Use for: "what's in bridge.py", "look at the .env", "show me that log file". The path goes in `delegation_task_hint`.
  Single-shot. Returns in seconds. **Cannot chain tools together.** "Search the web AND browse a URL AND screenshot" is THREE calls → tier 2. But "just check my git status" is one local_shell call → tier 1. "Just read bridge.py" is one read_file call → tier 1.

- **`delegation_tier: 2` (hand off to Claude Code).** Spawns a Claude Code subprocess with the FULL agent toolkit:
  - Bash / shell command execution
  - Full file read, write, edit in the user's workspace
  - Browser automation: navigate, click, fill forms, chained screenshots

  - MCP tools including PaLLi's own user-data MCP server
  - Multi-turn planning with verifier loops
  Minutes, not seconds. **REQUIRED** for: any task that needs more than one tool call chained (search→browse→screenshot→deliver), any task needing real file inspection/modification, any task needing shell command output, any task requiring browser interaction beyond fetching one URL. Tier 2 is where "find laptop deals on the east coast and send me pics" goes. Tier 2 is where "read bridge.py and explain function X" goes.

### Step 1: delegation_checklist (fill these in FIRST, honestly)

Three yes/no questions about THIS specific message. Answer from the capabilities above, not from surface keywords:

- `requires_multi_step_tools` (bool): Does a correct, complete answer require composing TWO OR MORE different tool operations in sequence? "Search the web, then open the best result, then screenshot, then send" is multi-step. "Just one web search for X" is NOT multi-step. "Find listings on a site, filter down, and send me pictures" IS multi-step. If yes, tier 1 cannot handle it (tier 1 is single-shot only).

- `requires_local_access` (bool): Does a correct answer require reading files on the user's machine, running shell commands, or inspecting local runtime state (git status, logs, running processes, config files)? "I could guess from training" does NOT count — only true if a genuinely correct answer requires local inspection. **Tier 1 NOW supports SINGLE-SHOT local access via `local_shell` and `read_file`.** Multi-step or multi-file local work is still tier 2.
  - Examples that ARE local_access: "read the README in this repo", "what does function X in file Y do", "check my git status", "what processes are running", "look at the logs for errors".
  - Examples that are NOT: "what does FastAPI do", "explain regex", "what's the capital of France".

- `benefits_from_ground_truth` (bool): Even if you feel confident answering from memory, would grounding the answer in actual file contents, current runtime state, or live web data make the answer MEANINGFULLY better or safer? Say true when answering-from-memory risks producing a confident-but-wrong answer (e.g. "summarize this file" when you haven't seen it). Say false for general knowledge, conversation, opinions, textbook answers.

### Step 2: derive delegation_tier from the checklist

Apply these rules IN ORDER — first match wins:

1. If `requires_multi_step_tools = true` → `delegation_tier = 2`. (Multi-step chains need Claude Code; tier 1 only allows a single tool call.)
2. If `requires_local_access = true` AND a SINGLE local-access call (one shell command OR one file read) would answer it → `delegation_tier = 1` with `tier1_tool="local_shell"` or `tier1_tool="read_file"`. (Pick local_shell for sysadmin / process / git / network operations; pick read_file for "what's in this file".)
3. If `requires_local_access = true` AND the work needs multiple files or multiple shell calls chained → `delegation_tier = 2`. (Tier-2 Claude Code is for multi-step local work.)
4. If `benefits_from_ground_truth = true` AND ONE of the in-house tier-1 tools (web_search, url_browse, screenshot, schedule_reminder, deliver_artifact, local_shell, read_file) would genuinely ground the answer → `delegation_tier = 1`.
5. Otherwise → `delegation_tier = 0`.

Your final `delegation_tier` MUST match this derivation. If you want a different tier than the rule gives you, your checklist answers are probably wrong — reconsider them against the capability manifest.
